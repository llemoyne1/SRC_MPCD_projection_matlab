# Weighted wallVP Poiseuille hotfix

This hotfix addresses two first-run issues in the weighted wall virtual particle
Poiseuille validation runner.

## Fixes

1. `resamp_apply_cell_thermostat_weighted` now accepts the optional
   `cellWetMask`/`wetMask` argument.  If provided, the thermostat is applied
   only to active fluid particles that are located in wet cells.  Existing
   callers without a wet mask remain unchanged.

2. `run_resamp_poiseuille_wallvp_validation` now calls
   `analyze_resamp_poiseuille_viscosity` with the profile-history structure
   expected by the analyzer.  The previous call used an unsupported
   `profileTable` name/value interface and could fail before producing a
   viscosity summary.

## Expected smoke

```matlab
outW = run_resamp_poiseuille_wallvp_validation( ...
    'steps',500, ...
    'sampleEvery',50, ...
    'summaryEvery',100, ...
    'Nx',64, ...
    'Ny',32, ...
    'gamma',20, ...
    'dt',0.005, ...
    'bodyForceX',0.005, ...
    'NMin',14, ...
    'NTarget',20, ...
    'NMax',26, ...
    'ThermostatStrength',0.25, ...
    'wallVirtualParticlesEnable',true, ...
    'rngSeed',12345);
```

The run should enter both `classic_wallvp_reference` and
`q6_resampled_wallvp` without the `cellwetmask` parser error.  The viscosity
analysis may still be physically poor if the flow is too short or not yet
parabolic, but it should not fail because of the call signature.
